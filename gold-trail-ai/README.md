# Gold Trail online photo analysis

This is an undeployed Cloudflare Worker adapter for an explicitly chosen online scan. The app posts a freshly re-encoded JPEG to /api/photo-analysis and sends an access code as a bearer token. It sends no EXIF, coordinates, filename or map context. This adapter sends the image to OpenAI's Responses API using a configured model, high image detail, structured output and store:false. OpenAI's retention policies still apply. A model response is not geological confirmation or a gold prediction.

Before production, configure an owner-controlled Cloudflare Worker with the PhotoQuota Durable Object binding, ALLOWED_ORIGIN (exact frontend HTTPS origin), a strong random ACCESS_CODE and OPENAI_API_KEY as server secrets, OPENAI_MODEL (for example gpt-6-astra, subject to account availability) and a positive integer DAILY_LIMIT. Access codes must be at least 32 characters. Use an independently generated high-entropy value; do not put secrets in source, logs or a public client bundle. DAILY_LIMIT is a shared daily ceiling, not a per-user billing control. Configure provider billing and additional platform rate limits. Verify real quotas, authentication, cost, retention, mobile CORS and model access before deployment. Never deploy an unprotected endpoint.

Run mock-only tests with node --test gold-trail-ai/worker.test.mjs. Mocks do not establish production security, model access, geological accuracy or phone performance. No server, credentials or model is provisioned by these files.

The browser re-encodes photos before sending; the adapter does not strip metadata from arbitrary direct clients. Origin checks alone are not authentication. Use a high-entropy access code, enforce additional edge rate limits, and verify a real Durable Object binding on a separately provisioned Cloudflare Worker; Sites support for this binding is not established. Browser cancellation stops waiting but may not stop a request or charges after the service receives it.
