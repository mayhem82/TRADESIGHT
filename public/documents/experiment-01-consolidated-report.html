TRADESIGHT — Experiment 01
Consolidated Continuity Report

SNAP-001 through SNAP-004 · 20 October 2026 · OPEN / NOT FINAL

Objective and scope

Real-world depth perception on Samsung S25 FE: validate actual depth acquisition, usable distances, stability and latency. Physical occlusion, windmill, cube, virtual models and synthetic depth were excluded from Experiment 01 at the user's direction.

Evolution and changes

The first WebXR prototype combined a windmill with depth-based occlusion (e639fb1, e7dbdf8). Interface repair followed (f022e1a). Repeated freezes prompted a smaller mesh and throttling (3e05894), temporary cube substitution (1e3d38f), and ultimately removal of all virtual geometry (e9c4d14, ab11b04). An undefined variable was fixed (45bcf38), and basic/depth sessions separated (c554fb5). Three.js and rendering were then removed for bare WebXR testing (d25f551, eabd953).

First confirmed milestone: basic AR

A user screenshot recorded immersive AR support at 11:22:54 and basic immersive AR session creation at 11:22:58. This established session creation, not depth sensing or camera tracking.

Second milestone: depth-enabled session

A screenshot recorded a depth-enabled AR session started at 11:50:15. The browser accepted the depth-sensing feature request, but no depth buffer was then confirmed.

Acquisition and controls

One-frame depth acquisition was added (8b425896). The user reported unresponsive READ DEPTH and END AR controls. Automatic acquisition and exit followed (59fdd43), then diagnostic instrumentation (5372e00) and a rebuilt WebXR frame lifecycle (0f2f9d7).

Third milestone: first depth buffer

At 12:51:07 a user screenshot confirmed a CPU depth buffer of 160 × 90 after 37 XR frames, with session exit. All five sample positions—centre, left, right, top and bottom—were invalid. Thus depth-buffer delivery is confirmed, but valid distances are not.

Latest unverified revision

Commit 8def1fc scans all 14,400 depth pixels, reports valid/zero pixel counts, minimum and maximum depth and the raw-to-metres scale, and waits if no valid values are present. No device outcome has yet been provided for this revision.

Learning and unresolved questions

Session creation, depth-enabled session creation and depth-buffer delivery are distinct milestones. Earlier freezes do not prove lack of depth support. Invalid samples may reflect zero depth, tracking, coordinate mapping or runtime behavior; no root cause is established. No accuracy, live throughput, end-to-end latency or long-term stability has been measured.

Alternative engines

Native ARCore Depth API is a live Android candidate; WebXR Depth Sensing is the browser path. Depth Anything V2 Small and MiDaS estimate relative image depth; Metric3D/UniDepth are metric-estimation candidates; DUSt3R/photogrammetry support multi-view reconstruction. None was benchmarked. 30 FPS and 15 FPS are proposed targets only.

Next validation gates

Run the full-buffer diagnostic and record valid pixel count, zero pixel count, range and conversion scale. Investigate coordinate mapping if valid pixels exist but centre samples fail; investigate tracking and runtime data if all pixels remain invalid. Validate against known physical distances before benchmarking latency.
